# v2.0.0 — Shared database cutover

Date: 2026-11-12. Status: Draft release notes.

Rimev moves to its prefixed tables in the shared pvnpll Supabase project. Existing users sign in again after the auth project changes. For email addresses already present in pvnpll, the existing pvnpll account and password are retained; Rimev-owned references are remapped during import. No sibling application tables or existing shared accounts are modified.

All application tables, indexes, constraints, and server policies use the `rimev_` prefix. The server connects with a dedicated role restricted to these tables. Browser access remains denied. The matching PostgreSQL driver adapter keeps Prisma queries unchanged and verifies TLS on both macOS and Vercel. PostgreSQL connections require TLS and validate Supabase's public CA certificate; the build includes that public certificate in server traces.

Prisma push, migrate, and reset npm commands are blocked before connecting because a partial application schema must not reconcile sibling tables. Client generation remains available.

Verification: schema validation, the full test/build check, a real TLS-validated destination connection, and a denied sibling-table read. Complete the final row-by-row comparison and deployed sign-in/library/statistics checks before retiring the original project. See `docs/database-cutover.md`.
